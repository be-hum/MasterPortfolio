# MasterPortfolio 제안서

- 작성일: 2026-11-24
- 상태: 초안 (기술 설계는 `docs/superpowers/specs/2026-11-24-masterportfolio-design.md` 참조)

## 1. 한 줄 요약

사용자가 이미 구독 중인 LLM(Claude, ChatGPT, Gemini)을 그대로 이용해, 내 PC 디스크 곳곳에 흩어진 과제·보고서·발표자료·코드 저장소에서 **이력서·자소서·포트폴리오에 쓸 수 있는 자료를 찾아 정리해주는** 로컬 도구.

## 2. 문제

- 취업 준비생은 수년간의 과제, 프로젝트, 공모전, 동아리 활동 자료를 여러 디스크와 폴더(Documents, Downloads, 대학 폴더, 프로젝트 폴더)에 흩어 보관한다.
- 이력서를 쓸 때 "무엇을 했는지"를 기억에 의존하게 되어, 쓸 만한 경험과 정량 성과를 빠뜨린다.
- 기존 AI 서비스에 자료를 올리려면 파일을 일일이 찾아 업로드해야 하고, 개인 자료를 낯선 서버에 보내는 부담이 있다.

## 3. 해결 방안

- **로컬에서 탐색**: 사용자가 확인한 폴더(여러 디스크 포함)를 스캔해 후보 파일을 로컬에서 먼저 거른다.
- **사용자의 LLM으로 분석**: Agent Client Protocol(ACP)로 사용자의 Claude Code / Codex CLI / Antigravity CLI를 구동한다. 추론은 사용자 구독으로 이뤄지며, 운영자 API 비용이 없다.
- **민감정보 보호**: 신분·금융 서류로 보이는 파일은 건너뛰고, 나머지는 주민번호·계좌번호 등을 로컬에서 마스킹한 뒤에만 LLM에 전달한다. 에이전트가 직접 파일을 읽지 못하게 한다.
- **이식성 높은 결과물**: 파일마다 Markdown 카드(YAML frontmatter)를 만든다. Obsidian, VS Code, 메모장 어디서든 열람·편집할 수 있다.
- **경험 단위 재구성**: 요청 시 파일 카드를 "경험 카드"(프로젝트/활동 단위, STAR 요약, 근거 파일 링크)로 묶고, 대화로 다듬는다.
- **기존 이력서 대조**: 이미 작성한 이력서·자소서를 기준으로 "이미 반영됨 / 부분 반영 / 미반영"을 표시해, 새로 발견한 경험을 드러낸다.

## 4. 대상 사용자

- 1차: Claude / ChatGPT / Gemini 중 하나 이상을 구독하고 해당 CLI 에이전트를 설치할 수 있는 취업 준비생·주니어 개발자.
- 운영 환경: Windows, macOS.

## 5. 범위

### 1차 (v1)

- 배포용 CLI (`mp`): `init`, `doctor`, `scan`, `rescan`, `status`, `group`, `chat`
- 입력 형식: PDF, DOCX, PPTX, DOC, PPT, MD/TXT, HWP/HWPX, 로컬 git 저장소
- 기존 이력서·자소서: 지정 폴더 하나에서 기준자료로 수집
- 여러 디스크 탐색, 선택적 관리자 권한 수집 모드(`--elevated`)
- 에이전트: Claude Code, Codex CLI (Antigravity `agy acp`는 내장 도구 차단 불가로 M3 재평가)

### 이후

- 로컬 웹 UI (같은 엔진 위), 필요 시 데스크톱 앱 패키징
- 채용 공고 맞춤 자료 추천
- 이미지·스캔본(수상 증명서, 자격증 사진 등)

### 범위 밖

- 원격 호스팅 웹 서비스 (로컬 디스크와 사용자 CLI 에이전트에 접근할 수 없음)
- 이력서·자소서 초안 자동 작성 (v1에서는 자료 정리까지)

## 6. 차별점

| 항목 | 일반 AI 이력서 서비스 | MasterPortfolio |
|---|---|---|
| 자료 수집 | 사용자가 직접 찾아 업로드 | 디스크를 스캔해 자동 발견 |
| 비용 | 서비스 구독 별도 | 이미 구독한 LLM 사용 |
| 데이터 경로 | 서비스 서버 경유 | 로컬 처리 + 사용자가 고른 LLM 벤더에만 마스킹된 텍스트 전달 |
| 결과물 | 서비스 안에 갇힘 | Markdown 파일로 자유롭게 이식 |

## 7. 주요 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 벤더 약관상 서드파티 클라이언트의 구독 계정 사용 허용 여부 | 구현 착수 단계(M0)에서 벤더별 확인, 결과 문서화. 불허 벤더는 지원 제외 |
| 에이전트 내장 도구로 원본 파일을 직접 읽어 마스킹 우회 | M0에서 에이전트별 도구 차단 가능 여부 검증. 불가 시 해당 에이전트 제외 또는 민감정보 정책을 "차단"으로 축소 |
| HWP 5.0 텍스트 추출 품질 | M0에서 Node 구현과 pyhwp 실측 비교. 부족하면 HWP 전용 Python 모듈 번들 |
| 구독 사용량 한도 | 로컬 사전 필터, 파일 묶음 전송, 중단 후 이어하기, 처리 개수 제한 옵션 |
| 마스킹 누락 | 보수적 패턴 + 명백한 민감 파일 스킵, 위험 판단 시 범위 축소 |

## 8. 성공 기준

- 사용자가 지정한 폴더에서 이력서·포트폴리오 활용 가치가 있는 파일을 찾아, 파일 카드로 정리한다.
- 정리된 카드 중 "기존 이력서 미반영" 항목에서 사용자가 실제로 이력서에 추가할 경험을 발견한다.
- 민감정보 패턴(주민번호·계좌·카드·여권·전화번호)이 LLM 전송 텍스트에 포함되지 않음을 로그로 확인할 수 있다.
- 지원 에이전트(v1: Claude Code, Codex) 중 어느 것을 써도 같은 형식의 결과물이 나온다.

## 9. 마일스톤

- **M0**: 검증 (HWP 추출, 에이전트 도구 차단, 약관)
- **M1**: 일반 권한 `init`/`scan` + 문서 추출기 + privacy + store + Claude Code 연동
- **M2**: HWP/HWPX·git 추출기, 기존 이력서 대조, `rescan`/`status`
- **M3**: Codex·Antigravity 연동, 여러 디스크 탐색, `--elevated`
- **M4**: `group` / `chat`
